## 別チャットで設計する際の共通方針

- 前提資料を読み、画面ID（S01〜S06）・機能ID（F01〜F14）を引き継ぐ。
- 各チャットは担当資料を中心に編集し、他資料への影響は記載して調整する。
- 未決定事項は、確定仕様と区別して記載する。
- この段階では設計を行い、アプリの実装やAzureリソースの作成・デプロイは行わない。

## バックエンド設計の調整事項

- API・機能・DBは共通の状態モデルとAPI IDを使用する。A14履歴削除とA15履歴詳細を追加、A11全ラウンド閲覧は廃止・欠番。
- 2026年10月14日の画面変更を反映。S02は累積額と履歴入口、S06は負け額中心の一覧・詳細・削除。削除は要件、論理削除・復元API非提供はB10の提案。
- 未決定の参加人数、一括操作、中断・再開、金額範囲、訂正、固定リスト運用・削除方式は、機能詳細のB01〜B10に提案をまとめている。
- 画面側には、未完了ゲームの再開・中止、未抽選者だけの一括操作、同点後の明示的な再抽選、保存前後の区別を反映する。一括操作途中・再開・中止は現モック未掲載のため調整対象。
- インフラのI06には、単一コンテナー`app`・`/ownerKey`、成功操作記録による冪等性、配置用権限での固定参加者登録を提案。ローカルDB方式は引き続き未決定。
- CORSはAPI定義のIf-Match・Idempotency-Key・X-Read-Sessionと、ETag等の公開応答ヘッダー、DELETEメソッドに対応する必要がある。

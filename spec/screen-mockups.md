# Roll & Pay — 画面モックアップ

状態：2026年10月14日に画面デザインを一旦確定後、同日の追加要望でホームから履歴を分離し、負け額中心の履歴と削除操作を反映。機能の詳細は後続の設計で詰める。

参照：[要件整理](../docs/requirements.md)／[画面一覧・機能一覧](../docs/screens-and-features.md)

## 開き方と確認範囲

[HTMLモック](mockups/index.html)をブラウザーで直接開く。ビルドやライブラリ導入は不要。

画面一覧とボタンのリンクで表示を切り替える。PCでは左側、スマートフォン幅では上部にモック確認用の画面一覧を表示する。

名前・日時・出目・金額は仮データ。チェック欄・金額入力欄は操作できるが、次の画面に値を引き継がない。認証・抽選・計算・保存は実行しない。サイコロはCSSと記号による表示例で、本番の3D描画は未実装。

## 全体の画面遷移

ログイン → ホーム → 参加者選択 → サイコロ → 会計入力 → 負担額確認 → 保存後の結果。

同点の場合は全員で振り直す。ホームから負け額の履歴一覧へ、一覧から個別詳細へ進む。保存後の結果からも個別詳細へ進める。詳細 → 削除確認 → 削除完了の表示例を用意する。

S04・S05・S06には複数の表示状態を用意した。

## 画面別モックアップ

スマートフォン優先の配置。操作・フォームの概要は各画面の説明欄にも記載している。

### S01 ログイン

[ログイン](mockups/index.html#login) / F01：管理者向けログイン案内。Microsoftログインのリンクでホームへ進む。本番では認証と管理者の権限確認を行う。

### S02 ホーム

[ホーム](mockups/index.html#home) / F03・F11：新規ゲームの入口と固定参加者全員の累積負け額を表示する。一度もゲームに参加していない人は「—」、参加済みで累積負け額が0円なら「0円」を表示する。初回は全員「—」。ゲーム履歴は置かず、履歴画面へのリンクを置く。

サンプルはあき・はる・ゆう・りんが参加済み、そら・なつが未参加。未参加と0円は金額だけでは区別できないため、バックエンド設計で参加実績を判別できる情報を用意する。中止ゲーム・削除済みゲームを参加実績に含めるかは後続で設計する。

### S03 参加者選択

[参加者選択](mockups/index.html#participants) / F02・F03：固定リストのチェック欄。開始リンクは固定4人のサイコロ画面へ進む。名前は仮データ、人数上限と名前の管理方法は未決定。

### S04 サイコロ

F04〜F06・F13：名前ごとのサイコロ、一括・個別操作、抽選状態、敗者を表示する。

| 状態 | モック | 操作・説明 |
|---|---|---|
| 未抽選 | [開始前](mockups/index.html#dice) | 個別サイコロまたは全員一括で振る。 |
| 抽選中 | [抽選中](mockups/index.html#dice-rolling) | 操作を無効表示。確認用リンクで同点・敗者確定の例を選ぶ。 |
| 操作待ち | [1人だけ確定](mockups/index.html#dice-waiting) | 全員の出目がそろうまで敗者を判定しない。リンクは全員完了の例へ進む。 |
| 同点 | [最小出目が同点](mockups/index.html#dice-tie) | 同点者を表示し、全員で振り直す。 |
| 再抽選 | [全員の振り直し](mockups/index.html#dice-reroll) | 全員の出目を未確定に戻し、一括・個別操作を提示。 |
| 敗者確定 | [ゆうに確定](mockups/index.html#dice-final) | 敗者を強調し、会計入力へ進む。振り直し操作は置かない。 |

### S05 金額確認／結果

F07〜F09・F12・F13：会計入力から保存後の共有用結果までを表示する。

| 状態 | モック | 操作・説明 |
|---|---|---|
| 会計入力 | [入力](mockups/index.html#payment) | フォームで整数円を入力する想定。確認リンクは13,800円・4人の固定例へ進む。 |
| 保存前 | [負担額確認](mockups/index.html#result) | 会計総額、各人の負担額、負け額を確認。入力へ戻るか保存後の例へ進む。 |
| 保存後 | [共有用の結果](mockups/index.html#saved) | 参加者・出目・敗者・金額を一枚のカードで表示。ホーム・履歴詳細へ進める。 |

負け額1,800円と敗者自身の負担4,800円を別に表示する。他の3人がゆうに各3,000円を渡し、ゆうが会計13,800円をまとめて支払う例を使う。

### S06 負け額の履歴／詳細

F10・F14：履歴の目的は、誰が・いつ・いくら負けたかを振り返ること。サイコロの抽選記録は画面から外す。バックエンドの抽選記録の保持・取得方針は別途設計する。

| 状態 | モック | 操作・説明 |
|---|---|---|
| 一覧 | [負け額の履歴](mockups/index.html#history-list) | ホームからゲーム履歴を移動。日時・敗者・負け額を中心に表示し、選択すると詳細へ進む。 |
| 詳細 | [個別詳細](mockups/index.html#history) | 日時、ゲーム当時の参加者名、敗者、会計総額、各自の負担額、負け額を表示。削除操作を置く。 |
| 削除確認 | [確認](mockups/index.html#history-delete) | 対象の日時・敗者・金額と、累積負け額からの除外を案内。キャンセルは詳細へ戻る。 |
| 削除完了 | [完了](mockups/index.html#history-deleted) | 1件だけあった履歴を削除した例。実データは変更しない。ホームは削除前の固定サンプル。 |

削除は履歴一覧と累積負け額の両方に反映する想定。論理／物理削除、復元可否、API、重複削除・保存との競合は後続の基本設計で扱う。

バックエンド資料のB07（履歴削除を初期版対象外とする提案）は今回の追加要望で見直し対象となる。機能詳細・API・DB設計にはF14の反映が必要。履歴閲覧の関連画面もS02/S06からS06中心へ調整する。

履歴一覧は計4件のサンプルを掲載。各記録から対応する詳細・削除確認へ進める。追加サンプルの負け額はホームの累積値と一致する。
